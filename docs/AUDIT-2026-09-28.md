# PyRoblox audit

Date: 2026-09-28

## Scope

- The committed code at HEAD `dc33b32` ("updating master function", 2024-09-30): the v1 package `robloxwrapper` with the `friends`, `groups`, `group_games` and `user_games` classes, `group_edgelist`, `friend_edgelist` and the `build_dataframes` pipeline that writes seven CSV files for a group.
- The uncommitted working tree as found at the start of the audit: 34 changed or untracked paths making up a half-finished refactor to a `RobloxClient` class hierarchy, a click CLI, dataclasses and an `analysis.py` module. The working tree has since been cleaned up for v2; the findings describe it as found.
- The Roblox module of the `tg_archiver` project on the `alex@fedora` machine, read over SSH to decide what could be reused in v2.
- A live probe of the public Roblox web APIs: 108 unauthenticated requests made on 2026-09-28, covering every endpoint the old code and the working tree call plus the documented public endpoints on each Roblox domain. The results are summarised in `docs/roblox-endpoints.md`.

## Summary

1. **`membership_<id>_edgelist.csv` is wrong for every group except the seed group.** The loop over the ally and enemy network calls `groups(group_id).user_list()`, where `group_id` is the seed group passed to `build_dataframes`, instead of the loop variable. Every ally and enemy group is written with the seed group's member list. Any membership network built from these files is the seed group's members repeated once per group. A knock-on effect is that `user_info_membership_<id>.csv` and `asset_info_<id>.csv` only cover the seed group's members, not the whole network the README promised.
2. **`asset_el<id>.csv` is garbage.** The favourites edgelist is built from `favorites_l`, the raw JSON of the last API response, instead of `favorites_el`, the list that accumulates the `[user, game]` pairs. The file has the right column names and none of the data. Separately, the pagination requests at most page 2 and then ignores it, so even the in-memory list held at most the first 50 favourites per user.
3. The working tree did not import. `import robloxwrapper` raised ImportError, all five test modules failed at collection, and zero tests ran.
4. The new `RobloxClient` sent every request to `https://api.roblox.com`, a host that no longer has a DNS record, and its games and assets clients called endpoints that do not exist on any Roblox host.
5. Packaging was broken: `pip install -r requirements.txt` fails because `time==1.0.0` is not a PyPI package, `setup.py` carried placeholder author fields and put `pytest` in the runtime dependencies, and `build/`, `*.egg-info`, `__pycache__`, `.DS_Store`, `.Rhistory` and a merge-conflict `.orig` file were committed. The README claims MIT but there was no LICENSE file.
6. Error handling in the v1 pipeline is `while True: try: ... except: time.sleep(60)`. A deleted group or a banned user makes it loop forever, and Ctrl-C is swallowed.
7. Roblox has changed since v1 was written. The friends list no longer returns names without a cookie; followers, followings and user badge lists now require a cookie; group wall posts and the games.roblox.com game-pass endpoint are gone; and several endpoints are limited to between 1 and 7 calls per minute per IP.
8. Neither tree served a non-programmer. There was no CSV output from the CLI, no single "collect everything" command, no progress or resume, no data dictionary, and no way to check that a cookie works.

## Findings

Each finding gives what is wrong, where it is, why it matters, and what v2 does about it.

### A. Import-breaking errors (working tree)

**A1. `robloxwrapper/__init__.py` imported things that did not exist.** It imported `friends` and `groups` from `get_friends` and `get_groups` (deleted in the working tree), the modules `.groups`, `.friends` and `.assets` (never created), and `Config` (the class was named `RobloxConfig`). Why it matters: `import robloxwrapper` failed, so nothing in the package could be used. v2: `__init__.py` exports only what exists and the test suite imports every module.

**A2. `analysis.py` called an API that was never written.** It imported the nonexistent `.groups` and `.friends` modules and called `get_members()`, `member.role`, `group_info.created` and `friend.updated`. None of these existed anywhere. v2: replaced by `collect.py`, whose collectors are tested against canned responses.

**A3. `tests/test_robloxwrapper.py` could not be collected.** It imported the removed `friends` and `groups` classes, required `vcr` (not installed and not declared), and called its own test functions at module import, so merely collecting the tests made network requests. v2: no network in the default test run; a `FakeSession` fixture serves JSON captured from the live probe.

### B. Wrong or invented endpoints (working tree)

**B1. Dead host.** `RobloxClient.BASE_URL = "https://api.roblox.com"`. Every `_make_request` in the new code targeted this host, and the README and config advertised `ROBLOX_API_URL=https://api.roblox.com`. The probe found no DNS A record for the name; curl reported "Could not resolve host". v2: each API class carries its own real base host (`users.roblox.com`, `groups.roblox.com`, and so on) and there is no configurable base URL.

**B2. Invented games endpoints.** `GamesClient` called `games/v1/games/{id}`, `games/v1/games/{id}/versions`, `/stats`, `/servers`, `games/v1/games?creatorId=` and `games/v1/users/{id}/favorites`. None exist. It also called `self._make_request(endpoint)` without the required `method` argument, so it would have raised TypeError even on a live host. v2: `GamesAPI` uses the verified `games/v1/games?universeIds=`, `games/v2/users/{id}/games`, `games/v2/users/{id}/favorite/games` and `games/v1/games/{placeId}/servers/Public`.

**B3. Fantasy dataclass.** `GameStats` declared about fifty fields (`total_bots`, `total_humans`, ...) that no Roblox response contains, and declared `total_verified` twice. v2: no dataclasses that pin field names. Methods return Roblox's JSON as dicts and lists and flattening happens at export time, so a field Roblox adds or renames does not break collection.

**B4. Invented asset endpoints.** `AssetsClient` called `/v1/assets/{id}`, `/v1/assets/{id}/versions`, `/v1/{users|groups}/{id}/assets` and `/v1/users/{id}/favorites`. All invented. v2: `AssetsAPI` uses `economy.roblox.com/v2/assets/{id}/details` and `catalog.roblox.com/v1/catalog/items/details`, both verified live.

**B5. Social links call could not run.** `GroupsClient.get_social_links()` passed `cookies=` to `_make_request`, which had no such parameter: TypeError. v2: the cookie lives on the client session and is sent only to `*.roblox.com` hosts.

**B6. Unverified page size.** `GroupsClient.get_allies` and `get_enemies` requested `model.maxRows=100000`. The probe only verified `model.maxRows=100`. v2: pages allies and enemies 100 rows at a time using the `nextRowIndex` field.

**B7. Two `build_dataframes`.** The v1 one in `build_dataframes.py` and a stub in `analysis.py`; `__init__.py` exported the old one. v2: one implementation, `collect.group_network`, with `build_dataframes` kept as a thin compatibility wrapper that writes the same seven file names.

### C. Data-corrupting bugs in the committed pipeline (`robloxwrapper/build_dataframes.py` at HEAD)

**C1. Membership edgelist uses the seed group for every group.**

```python
for i in list(group_ids):
    while(True):
        try:
            print(i)
            friends_list = groups(group_id).user_list()
            for j in friends_list['data']:
                group_el.append([i, j['user']['userId']])
```

`group_id` is the argument to `build_dataframes`. `i` is the ally or enemy group being processed. The member list fetched is always the seed group's, and it is paired with `i`. Consequence: in `membership_<id>_edgelist.csv`, every row whose `Group` column is not the seed id is false. Because `user_ids` is derived from that edgelist, `user_info_membership_<id>.csv`, `asset_el<id>.csv` and `asset_info_<id>.csv` cover only the seed group's members. v2: `group_network` calls `members(i)` for each group, and a unit test asserts that the group id in every edge matches the group whose members were requested.

**C2. Favourites edgelist built from the wrong variable.**

```python
favorites_l = user_games(i).favorites_list()
...
asset_el_df = pd.DataFrame(favorites_l, columns=["User", "FavoritedGame"])
```

`favorites_l` is the raw response dict (`previousPageCursor`, `nextPageCursor`, `data`) of whichever request ran last. The list that actually accumulates `[user, game]` pairs, `favorites_el`, is never written anywhere. `asset_el<id>.csv` therefore contains no edges. v2: writes the accumulated edge list and tests it.

**C3. Favourites pagination stops after page 2 and discards it.**

```python
cursor = favorites_l['nextPageCursor']
favorites_l = favorites_l = user_games(i).favorites_list(cursor=cursor)
```

The second page is requested (even when `cursor` is `None`, which re-fetches page 1) and then nothing iterates over it. So `favorites_el` and `games_dict`, the source of `asset_info_<id>.csv`, hold at most the first 50 favourites per user. v2: the client follows `nextPageCursor` until it is null and the collector tests cover multi-page responses.

**C4. Bare `except` with retry forever.**

```python
while(True):
    try:
        ...
    except:
        time.sleep(60)
        continue
    break
```

This wraps every network call in the pipeline. A bare `except` catches `KeyboardInterrupt`, so Ctrl-C does not stop the run. It also catches permanent errors (a deleted group, a banned user's favourites, a locked group's relationships all return 400 or 404), so the loop never ends. The membership loop has `except: continue` with no sleep, so a permanent error hammers Roblox without pause. v2: typed exceptions (`NotFoundError`, `PrivateError`, `AuthRequiredError`, `BadRequestError`, `RateLimitedError`); a failed secondary lookup is recorded in the snapshot's `omitted` list and collection continues; `KeyboardInterrupt` is never caught.

**C5. Group info key filter raises before the error check.**

```python
group_info = groups(i).info()
group_info = dict((k, group_info[k]) for k in (['id', 'name', 'description', 'owner', 'shout', 'memberCount', 'isBuildersClubOnly', 'publicEntryAllowed', 'hasVerifiedBadge']))
if "errors" in group_info.keys():
```

When Roblox answers `{"errors": [...]}`, the dict comprehension raises `KeyError` on `'id'`, so the `if "errors"` guard is never reached and the bare `except` in C4 retries forever. v2: the client raises a typed error on Roblox error bodies before any key is read.

**C6. Social links fetched and then lost.** The pipeline calls `groups(i).social_links(cookies = cookie)`, the only reason it demands a cookie, and appends the links to each group's row. The DataFrame is then declared with only the nine group-info column names. At HEAD any row with links has more values than columns and pandas rejects the row list; the working-tree copy avoided that by slicing each row to its first nine values. Either way the links never reach `group_info_<id>.csv`. v2: `group_snapshot` writes a separate `social_links` table when a cookie is present.

**C7. Output hygiene.** All seven CSVs go to the current directory with the pandas index as an unnamed first column; `group_info_<id>.csv` is written twice; there is no output directory option. v2: `Snapshot.save(out_dir)` writes `index=False` CSVs plus a manifest into a named folder.

**C8. `friends_edgelist.py` and `groups_edgelist.py`.** Same pattern: bare `except` followed by `time.sleep(60)` and silent loss of that node's edges, ids printed to stdout as progress, no deduplication, no depth option. v2: `friend_network(depth=, max_users=)` and `group_network(max_groups=)` with logging and per-step progress lines.

**C10. Favourites request is rejected by today's API.** `user_games.favorites_list` requested `games.roblox.com/v2/users/{id}/favorite/games?sortOrder=Asc&limit=50`. Roblox now answers 400 "Ascending sort order is not supported for user's favorite games." for that query (confirmed live on 2026-09-28 for users 1 and 261). Under the bare `except` in C4 the pipeline would sleep 60 seconds and retry forever on the first user. v2: no sort order is sent on this endpoint, and the compatibility shim was corrected too.

**C9. Merge-conflict file committed.** `robloxwrapper/build_dataframes.py.orig` with conflict markers is in the repository. v2: removed.

### D. Packaging and hygiene

**D1. `setup.py`.** Author "Your Name", URL "yourusername", `pytest` in `install_requires`, `pyyaml` (imported by `cli.py`) and `networkx` (imported by `analysis.py`) missing, version regressed from 1.0 to 0.1.0. `find_packages()` together with an empty root-level `__init__.py` and `tests/__init__.py` installed `tests` as a top-level package. v2: `pyproject.toml` with real metadata; runtime deps `requests`, `click`, `pandas`, `pyyaml`, `networkx`; `pytest` in a dev extra; version 2.0.0.

**D2. `requirements.txt`.** Pinned `requests==2.11.1` (2016), `pytest==3.0.3`, `vcrpy==1.10.3` and `time==1.0.0`. The last is not a PyPI package, so the file cannot be installed. v2: removed; dependencies live in `pyproject.toml`.

**D3. Committed junk.** `build/`, `PyRoblox.egg-info/`, `__pycache__/*.pyc` for Python 3.8, 3.9 and 3.12, four `.DS_Store` files, `.Rhistory`, the `.orig` file, and a duplicate `tests/tests/vcr_cassettes/` directory. No `.gitignore`. v2: all removed and a `.gitignore` added.

**D4. Licence.** The README claims MIT; there was no `LICENSE` file. v2: `LICENSE` (MIT) added.

**D5. Working-tree README described software that did not exist.** It documented `roblox users info`, `groups relationships`, `users favorites`, `get_members`, `get_relationships`, `get_friend_count`, `Config` and `build_dataframes(group_id=, user_id=, output_dir=)`, gave the wrong env var default (`ROBLOX_API_URL=https://api.roblox.com`), and described config keys the CLI loader did not read (`test_cli.py` used nested `authentication:` and `output:` keys; `cli.py` read neither). v2: README and `docs/` are written from the code that exists, and the CLI tests exercise the documented commands.

**D6. HEAD README was also wrong.** It documented `rw.user_info()` and `rw.group_info()`, which never existed, and `from PyRoblox import robloxwrapper`, which does not work because the import name is `robloxwrapper`.

**D7. `test_cli.py::test_cli_help`** asserted a help string that did not match the command's docstring.

**D8. `cli.py` inconsistencies.** The module defined a function named `info` three times (for `friends`, `assets` and `games`), and the games commands used `pass_obj` while the others used `pass_context` with `ctx.obj['config']`, so the games commands received a plain dict rather than a `RobloxConfig`. v2: one command module with one config object passed the same way everywhere.

### E. Usability gaps for researchers

- No one-command "collect everything about user or group X into a folder of CSVs". v2: `roblox user snapshot`, `roblox group snapshot`, `roblox game snapshot`, `roblox user network`, `roblox group network`.
- The working-tree CLI wrote JSON only. v2: CSV by default, `--format json` optional.
- No progress reporting for multi-hour runs. v2: logging at INFO, per-step progress lines in the CLI, and `max_items`, `max_users` and `max_groups` caps. Resume is still not implemented; files written before a Ctrl-C are kept.
- The new README dropped the cookie instructions the old one had. v2: `docs/roblox-endpoints.md` says which endpoints need a cookie, where to find it and how to store it.
- No data dictionary explaining the columns. v2: `docs/data-dictionary.md`.
- No way to check connectivity or the cookie. v2: `roblox check`.
- Bare `except` hid what was and was not collected. v2: every snapshot writes a manifest listing omitted tables and errors.

## What changed in the Roblox API since v1

All of the following was observed in the live probe on 2026-09-28 without a cookie.

- `GET games.roblox.com/v2/users/{id}/favorite/games` rejects `sortOrder=Asc` with 400 "Ascending sort order is not supported for user's favorite games." (v1 sent exactly that). Without a sort parameter it returns 200, newest first.
- The friends list can contain entries with `id: -1` and empty names (three of the 98 entries for user 261). These stand for deleted or hidden accounts. v2 keeps them in the `friends` table as Roblox sent them but does not add them to friend networks (`meta["hidden_friends_skipped"]` counts them).
- `GET friends.roblox.com/v1/users/{id}/friends` still returns the complete list of friend ids in one response (98 entries for user 261, matching `friends/count`), but `name` and `displayName` are empty strings for every entry. Names must be resolved with `POST users.roblox.com/v1/users` (1000 calls per second, 100 ids per call). The v1 `friend_edgelist` only used ids, so it is unaffected; anything that read names from this response is.
- `GET friends.roblox.com/v1/users/{id}/followers` and `/followings` return 401 "Authentication token is missing". The `/count` variants still work without a cookie.
- `GET badges.roblox.com/v1/users/{id}/badges` returns 401; it used to be public. `GET .../badges/awarded-dates` returns 403.
- `GET groups.roblox.com/v1/groups/{id}/wall/posts` returns 404 "NotFound" for both a locked group and the public group 7. The endpoint is gone for unauthenticated callers.
- `GET games.roblox.com/v1/games/{universeId}/game-passes` returns 404. Game passes moved to `GET apis.roblox.com/game-passes/v1/universes/{universeId}/game-passes`, which returns a top-level `gamePasses` array.
- `GET accountinformation.roblox.com/v1/users/{id}/promotion-channels` returns 200 without a cookie but every value is null, including for two large creators (user ids 339310190 and 140258990). Treat the values as masked unless a cookie is supplied.
- `api.roblox.com` has no DNS record. Any code built on it fails before a request is sent.
- `GET groups.roblox.com/v1/groups/{id}` now includes a `communityTier` object. `GET users.roblox.com/v1/users/search` hits now include a `previousUsernames` list.
- Cursor-paginated list endpoints reject any `limit` other than 10, 25, 50 or 100 (HTTP 400 with `field: limit`). `games/v2/users/{id}/games` accepts at most 50.
- For a locked group (`isLocked: true`), allies, enemies and name-history all return 400 "Group is invalid or does not exist."
- `GET games.roblox.com/v1/games/{id}/servers/Public` takes a place id. A universe id returns 400 "The place is invalid."
- `POST catalog.roblox.com/v1/catalog/items/details` answers the first call with 403 "XSRF token invalid" and an `x-csrf-token` response header; retrying with that header succeeds.
- Roblox sends `x-ratelimit-limit`, `x-ratelimit-remaining` and `x-ratelimit-reset` on every response. Limits are per IP and per endpoint, not per host. The tight ones:

| Limit per IP | Endpoint |
|---|---|
| 1 per 60 s | `GET users.roblox.com/v1/users/{id}/username-history` |
| 1 per 60 s | `GET users.roblox.com/v1/users/search` |
| 1 per 60 s | `GET inventory.roblox.com/v1/users/{id}/can-view-inventory` |
| 1 per 1 s | `GET groups.roblox.com/v2/groups?groupIds=` (batch; up to 100 ids per call) |
| 3 per 60 s | `GET games.roblox.com/v1/games/{placeId}/servers/Public` |
| 3 per 1 s | `GET games.roblox.com/v2/groups/{id}/games` and `/gamesV2` |
| 6 per 60 s | `GET avatar.roblox.com/v1/users/{id}/currently-wearing` |
| 7 per 60 s | `GET groups.roblox.com/v1/groups/{id}` |
| 10 per 60 s | `GET catalog.roblox.com/v1/users/{id}/bundles`; `GET catalog.roblox.com/v1/favorites/users/{id}/favorites/{type}/assets`; `GET badges.roblox.com/v1/users/{id}/badges/awarded-dates` |
| 15 per 60 s | `GET inventory.roblox.com/v2/assets/{id}/owners` |
| 20 per 60 s | `GET friends.roblox.com/v1/users/{id}/friends` |
| 30 per 60 s | `GET users.roblox.com/v1/users/{id}`; `GET groups.roblox.com/v1/groups/{id}/roles/guest/permissions` |

A second call to a 1-per-minute endpoint inside the window returned 429 with `retry-after: 5`. A call to `users/search` followed 1.2 seconds later by a call to `username-history` both succeeded, which shows the buckets are per endpoint. The v1 pipeline's one `groups(i).info()` per group would now be throttled after the seventh group; that is why v2 uses the single-group GET only for the seed group and the batch endpoint for the rest.

## Method

1. Static read of every Python file, test, cassette, README and packaging file at HEAD and in the working tree, following each import and each call to check that the target exists and the arguments match its signature.
2. Ran the working-tree test suite. Zero tests executed; all five modules failed at collection with import errors.
3. Live probe: 108 unauthenticated HTTP requests to the Roblox web APIs on 2026-09-28, sequential at about one per second with a browser `User-Agent`. The set covered every endpoint used by the v1 code, the working tree and the `tg_archiver` module, plus the documented public GET endpoints on each domain. For each request the status, the `x-ratelimit-*` headers, the content type and the body were recorded. Boundary cases were sent deliberately: `limit=101`, a universe id where a place id is expected, a locked group, an id that is not a user, and a second call to a 1-per-minute endpoint inside the window.
4. Read the `tg_archiver` Roblox module over SSH (its client, its capture policy and its tests) to decide what could be reused. Its client, best-effort capture policy and test fakes are the basis of the v2 design.
5. Pulled the Roblox reference pages at `https://create.roblox.com/docs/cloud/reference/domains/<domain>.md` for each domain to list the documented GET endpoints and which ones the documentation marks as requiring authentication, and confirmed that the old `<domain>.roblox.com/docs` swagger pages now redirect there or return 404.
